Key Projects

Distributed Stateful Workflow Orchestrator

Coordinating long-running customer-interaction flows across 6+ services — one dropped handoff under load becomes hours of unreproducible cross-service inconsistency. Decision: TTL-based distributed locks over an external lock service (smaller operational surface); a strategy-switchable routing engine (load-balancing / affinity / failover per flow type) instead of a hardcoded policy. Result: cross-service recovery moved from incident-driven firefighting to process-driven operations, flow events sunk into Kafka for SRE / analytics self-serve tracing.

Tech: Go, Kafka, NATS, MongoDB, gRPC, Jaeger

EPA Air Quality iOS App — 1M+ downloads, 2 government innovation awards

Consumer environmental-data app whose users mostly opened it on commuter MRT or in low-signal rural areas — 'requires network to be useful' was a guaranteed uninstall. Decision: chose a CoreData-backed offline-first design over request/response, MQTT subscription over REST polling (cellular / battery), and CoreLocation significant-location-change over continuous GPS (background-limit / battery survival). Result: 1M+ downloads, 2,000+ DAU, Information Month Top 100 Innovation Award (2017–2018) and Smart City Innovation Award (2018).

Tech: Swift, CoreData, MQTT, CoreLocation, Charts

i-Plants Crop Traceability + Government-commissioned iOS App Series

Built with the Council of Agriculture for field workers — actual usage context is unstable cellular signal, muddy gloves, one-handed operation. Decision: chose offline-first as default and network as option (not the more common online-first design) — every QR scan and form submission wrote to local SQLite, diff-sync only on reconnect; UI built around large single-tap targets instead of typical city-app tab-bar. The principle: 'treat the network as optional, not the default.' Result: delivered to multiple government units, featured in ChinaTimes and Agricultural Media; same architecture reused across 2 follow-on commissioned projects without rewrites.

Tech: Swift, SQLite, RESTful API, MapKit, CoreLocation, QR Code

Zenbo Cross-device VoIP SDK (ASUS Smart Robot)

ASUS Zenbo robots needed real-time audio/video calls with iOS devices, but the robot runtime is not standard iOS — signaling, NAT traversal, and call lifecycle had to be designed from scratch, and other product teams shouldn't be forced to learn WebRTC just to embed calling. Decision: shipped negotiation, NAT traversal, and call state machine as a single-entry SDK rather than exposing raw WebRTC primitives; iOS side and robot runtime shared the same call-state model, killing an entire category of cross-device race conditions before they could exist (no second state machine to drift). Result: other teams embedded Zenbo↔iOS calling with a handful of API calls; SDK became the foundation of ASUS smart-robot calling.

Tech: Swift, WebRTC, VoIP, APNS, NAT Traversal

Real-time Multiplayer Game Networking Layer + E2E Encryption

Real-time multiplayer game whose state had to remain consistent on lossy mobile networks, with in-game financial flows that had to clear a strict pre-launch security audit. Decision: for networking, built message framing and reconnection on raw GCDAsyncSocket + Protocol Buffers rather than dropping in a generic socket library — frame ordering and partial-state replay needed packet semantics no general library would model correctly. For the financial flow, layered ECDSA / ECDH end-to-end encryption on top of TLS rather than relying on TLS alone — payloads stay unreadable even if transport is compromised. The principle: 'don't outsource the parts where the game would die.' Result: game state stayed consistent under unstable mobile networks; financial flow cleared the security audit on first pass.

Tech: Objective-C, Swift, GCDAsyncSocket, Protocol Buffers, OpenSSL (ECDSA/ECDH)
