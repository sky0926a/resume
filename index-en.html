03. Selected Projects

Backend · Distributed

Distributed Stateful Workflow Orchestrator

Coordinating long-running customer-interaction flows across 6+ services — the kind of system where a single dropped handoff under load turns into hours of cross-service inconsistency no single team can reproduce. Decision: TTL-based distributed locks over an external lock service to keep the operational surface small; a strategy-switchable routing engine (load-balancing / affinity / failover per flow type) rather than a hardcoded policy, so new flow types never touch core code. Result: cross-service recovery moved from incident-driven firefighting to process-driven operations, with flow events sunk into Kafka so SRE and analytics can self-serve full-lifecycle tracing.

  • TTL-based locks over an external lock service — minimized operational surface
  • Strategy-switchable routing (not hardcoded) — new flow types don't touch core
  • Flow events → Kafka — SRE / analytics self-serve tracing
  • Recovery ran as process, not firefighting

iOS · Award-winning

EPA Air Quality iOS App — 1M+ downloads, 2 government innovation awards

A consumer environmental-data app whose users mostly opened it on commuter MRT or in low-signal rural areas — meaning 'requires network to be useful' was a guaranteed uninstall. Decision: chose a CoreData-backed offline-first design over a request/response model so every screen still rendered against the last known snapshot when connectivity dropped; subscribed to live station data via MQTT instead of REST polling to cut cellular and battery cost; used CoreLocation significant-location-change rather than continuous GPS for proximity alerts so the app didn't get killed by iOS background limits or drained the battery enough to be deleted. Result: 1M+ downloads, 2,000+ DAU, awarded the Information Month Top 100 Innovation Award (2017–2018) and the Smart City Innovation Award (2018).

  • Offline-first via CoreData snapshot — works in MRT / rural blackspots
  • MQTT subscription over REST polling — cellular and battery friendly
  • Significant-location-change over continuous GPS — survives background limits

Result: delivered to the Council of Agriculture and multiple government units, featured in ChinaTimes and Agricultural Media; the same offline-first architecture was reused across the next 2 commissioned projects without rewrites.

iOS · Cross-device SDK

Zenbo Cross-device VoIP SDK (ASUS Smart Robot)

ASUS Zenbo robots needed real-time audio/video calls with iOS devices, but the robot runtime is not standard iOS — signaling, NAT traversal, and call lifecycle all had to be designed from scratch, and other product teams shouldn't be forced to learn WebRTC just to embed calling. Decision: shipped the entire negotiation, NAT traversal, and call state machine as an SDK with a single entry point rather than exposing raw WebRTC primitives — so other teams could embed video calling without touching ICE candidates or SDP munging. The robot-side hardware integration and the iOS side shared the same call-state model rather than each maintaining its own — this killed an entire category of cross-device race conditions before they could happen, because there was no second state machine to drift out of sync. Result: other product teams embedded Zenbo↔iOS video calls with a handful of API calls; the SDK became the foundation of ASUS smart-robot calling capability.

  • Single-entry SDK over raw WebRTC primitives — protect consumers from ICE/SDP
  • Shared call-state model across iOS and robot runtime — kills cross-device races structurally
  • Cross-domain hardware integration on a non-standard iOS runtime
  • Foundation of ASUS smart-robot calling capability

iOS · Realtime · Crypto

Real-time Multiplayer Game Networking Layer + E2E Encryption

A real-time multiplayer game whose gameplay state had to remain consistent across players on lossy mobile networks, and which contained in-game financial flows that had to clear a strict pre-launch security audit. Decision: for the networking layer, chose to build the message framing and reconnection protocol on raw GCDAsyncSocket + Protocol Buffers rather than dropping in a generic socket library — because game frame ordering and partial-state replay needed packet semantics no general-purpose library would model correctly. For the financial flow, chose end-to-end encryption with OpenSSL ECDSA / ECDH on top of TLS rather than relying on TLS alone — so an intercepted payload remained unreadable even if the game's transport layer was compromised. The principle was 'don't outsource the parts where the game would die.' Result: game state stayed consistent under unstable mobile network conditions; the financial flow cleared the project's pre-launch security audit on first pass.

  • Custom framing + reconnection on GCDAsyncSocket — over generic socket libraries
  • Frame ordering and partial-state replay tuned to game semantics
  • ECDSA / ECDH end-to-end encryption layered on top of TLS
  • Cleared pre-launch security audit on first pass
