Key Projects

分散式 Stateful Workflow 核心

串接 6+ 個服務的長時運行客戶互動流程 — 一次流量尖峰下的 handoff 漏掉就變成跨服務、沒人能重現的數小時不一致事故。決策: 選用 TTL-based 分散式 lock 而非外部 lock 服務(降低維運表面);路由引擎做成策略可切換(依流程類型切負載平衡 / 親和性 / 故障轉移),而非寫死單一策略。結果: 跨服務事故處理從救火轉為流程驅動,流程事件下沉至 Kafka,SRE / analytics 可自助追蹤完整生命週期。

Tech: Go, Kafka, NATS, MongoDB, gRPC, Jaeger

環保署空氣品質 iOS App — 百萬下載、政府雙獎

消費端環境資料 App,使用者大多在通勤捷運或低訊號鄉村開啟 — 「需要網路才能用」就等於必被解除安裝。決策: 選擇 CoreData offline-first 而非 request/response;MQTT 訂閱取代 REST polling(cellular / 電力);CoreLocation significant-location-change 取代持續 GPS(背景限制 / 電力存活)。結果: 百萬下載、2,000+ DAU,獲 2017–2018 資訊月百大創新產品獎 與 2018 智慧城市創新應用獎。

Tech: Swift, CoreData, MQTT, CoreLocation, Charts

i-Plants 農食履歷 + 政府委託 iOS App 系列

與農委會合作,使用者是農場田間人員 — 訊號不穩、雙手沾泥、單手操作。決策: 選擇 offline-first 為預設、網路為選配,而非常見的 online-first 設計 — QR 掃描與表單填寫直接寫入本地 SQLite,連線恢復時才差異同步;UI 以大型單點按鈕為主而非典型 tab-bar。原則:「網路是選配,不是預設」。結果: 順利交付給多個政府單位,獲 中時電子報、農傳媒專題報導;同套架構在後續 2 項委託專案中複用不需改寫。

Tech: Swift, SQLite, RESTful API, MapKit, CoreLocation, QR Code

Zenbo 跨裝置 VoIP SDK(ASUS 智慧機器人)

ASUS Zenbo 機器人需要與 iOS 即時通話,但機器人 runtime 不是標準 iOS — 信令、NAT 穿透、通話生命週期皆需自行設計,其他團隊不應該被迫學 WebRTC 才能用通話。決策: 將協商、NAT 穿透、狀態機 包成單一進入點 SDK,而非暴露 raw WebRTC;iOS 與機器人 runtime 共用同一份 call-state model,在問題發生前消滅整類跨裝置 race(沒有第二個狀態機可漂移)。結果: 其他團隊以少量 API 即可嵌入 Zenbo↔iOS 通話;SDK 成為 ASUS 智慧機器人通話能力底層。

Tech: Swift, WebRTC, VoIP, APNS, NAT Traversal

即時多人遊戲通訊層 + 端對端加密

即時多人遊戲,遊戲狀態必須在不穩定行動網路下維持一致;內含真實金流,通過嚴格上架前安全審計為必要條件。決策: 通訊層 基於 GCDAsyncSocket + Protocol Buffers 自行設計封包與重連協定,而非套用通用 socket library — 遊戲 frame 順序與部分狀態 replay 需要的封包語意沒有通用 library 會正確建模。金流 在 TLS 之上加 ECDSA / ECDH 端對端加密,讓金流訊息即使被攔截也無法解開。原則:「會讓遊戲死掉的地方不要外包」。結果: 遊戲狀態於不穩定行動網路下保持一致;金流一次通過上架前安全審計。

Tech: Objective-C, Swift, GCDAsyncSocket, Protocol Buffers, OpenSSL (ECDSA/ECDH)
